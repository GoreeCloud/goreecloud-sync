# Competitive Objectives

GoreeCloud Sync is intended to equal or exceed the useful capabilities of mature synchronization and transfer tools while preserving GoreeCloud ownership, privacy, security, recoverability, and interoperability requirements.

## Initial benchmarks

### Syncthing

Benchmark areas:

- persistent peer-to-peer folder synchronization;
- device discovery and explicit device trust;
- send/receive, send-only, and receive-only folder behavior;
- ignore patterns;
- file versioning;
- conflict preservation;
- resumable replication;
- private-network and relay-compatible connectivity.

GoreeCloud differentiators planned beyond the benchmark include native multi-user authorization, unified Nearby and Share workflows, GoreeCloud Identity integration, recovery-awareness, and a simpler Glaze UI administration model.

### LocalSend

Benchmark areas:

- low-friction nearby discovery;
- local-network file and text transfer;
- accountless local use;
- platform sharing integration;
- transfer resume and verification;
- favorite/trusted devices;
- offline operation.

GoreeCloud differentiators planned beyond the benchmark include persistent synchronization, explicit multi-user policy, private-network operation, centralized administration, and controlled share-link delivery.

### wormhole.app

Benchmark areas:

- temporary encrypted sharing;
- recipient-friendly browser delivery;
- expiration;
- direct transfer when possible;
- encrypted temporary storage when direct delivery is unavailable.

GoreeCloud differentiators planned beyond the benchmark include self-hosted coordination, multi-user policy, device identity, configurable download/recipient controls, and integration with the rest of the GoreeCloud Suite.

## Product objectives

The project should eventually provide:

- one coherent application for Sync, Nearby, and Share;
- self-hosted control without mandatory third-party accounts;
- native multi-user isolation;
- explicit per-device ownership and revocation;
- conflict transparency;
- transfer integrity states distinct from transfer completion;
- migration tooling;
- drop-only contribution workflows;
- privacy by default;
- Wardveil Security and Privacy Shield integration;
- Everkeep recovery-awareness;
- GoreeCloud Network integration;
- portable data and documented exit paths;
- no advertising or sponsorship-driven behavior.

## Evidence rule

A capability belongs in the implemented column only after source and appropriate runtime validation exist. Planned capability must not be presented as shipped functionality.

Competitive work may learn from public behavior, standards, documentation, and lawfully reusable open-source implementations, but must not copy proprietary assets, protected trade dress, confidential information, or incompatible source code.
