# Benefits

GoreeCloud Sync is being designed to reduce the number of separate tools required to move and synchronize private data while keeping authorization, security, and recovery boundaries understandable.

## Intended benefits

### Ownership and control

Self-hosted operation and open source code reduce dependence on a single transfer provider, synchronization vendor, or hosted account system.

### One coherent transfer model

Sync, Nearby, and Share are intended to cover persistent replication, immediate device transfer, and temporary recipient-friendly delivery without forcing users to learn unrelated products for each workflow.

### Native family and multi-user administration

Per-person accounts, per-device identity, and explicit folder permissions are intended to make family use safer than a shared unrestricted synchronization identity.

### Privacy by default

The product is designed without advertisements, behavioral tracking, sponsorship-driven behavior, or mandatory analytics. Direct paths are preferred when practical, and temporary infrastructure should retain only what is needed for its approved role.

### Safer recovery posture

GoreeCloud Sync explicitly avoids presenting synchronization as backup. Recovery-awareness can help users recognize when synchronized information still lacks independent protection.

### Transparent conflicts and integrity

The planned Conflict Center and explicit verification states are intended to reduce silent data loss and distinguish “bytes transferred” from “content verified.”

### Better GoreeCloud interoperability

First-party integration can provide consistent identity, private networking, notifications, administration, storage destinations, privacy controls, security controls, and recovery visibility without collapsing those systems into one trust boundary.

### Portability

Documented protocols, export paths, open-source implementation, and technology-independent storage boundaries are intended to keep data movable even if the application or infrastructure changes later.

## Status

These are product objectives. Only benefits directly supported by implemented and validated features should be presented as current release behavior.
